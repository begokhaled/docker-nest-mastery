High-Level Topology

Notice how development gives direct access to all database ports for local inspection, while production funnels everything exclusively through Nginx into an isolated private bridge network.

🛠️ Development Stack (docker-compose.yml)
  • NestJS Container: Runs nodemon watching mounted ./src volume. Exposes port 3000 and debugger 9229.
  • PostgreSQL 16: Host port 5432 open for tools like DBeaver, TablePlus, or pgAdmin.
  • MongoDB 7: Host port 27017 open for MongoDB Compass.
  • Redis 7: Host port 6379 open for RedisInsight or CLI.
  • Health-Check Dependencies: api container does not boot until Postgres, Mongo, and Redis report healthy.
🚀 Production Stack (docker-compose.prod.yml)
  • Nginx Proxy: Only public entrypoint on Port 80 (and 443). Enforces rate-limiting (20 req/s), security headers, and gzip.
  • NestJS Container: Runs compiled JS (node dist/main.js) as unprivileged non-root node user. No ports exposed to host.
  • Databases (Postgres, Mongo, Redis): Completely sealed inside internal network prod_network. Zero public attack surface.
  • Resource Caps: Memory limits (512MB for API & DBs, 256MB for Redis) and CPU throttling.

Healthy Dependency Pattern

This guarantees that the databases are actually accepting TCP connections before NestJS boots.

03

Multi-Stage Dockerfile Deep Dive

Why use multi-stage builds? Because standard Dockerfiles bundle compilers, linters, and heavy development tools into the final image, ballooning image sizes to 1.5GB+ and exposing unnecessary security vulnerabilities.

🛡️ Signal Handling with dumb-init

In Docker, the process running as PID 1 does not receive standard Linux signals (SIGTERM / SIGINT) by default. When you run docker stop, Node.js ignores the signal and Docker forcefully kills it with SIGKILL after 10s.

Dockerfile instruction
RUN apk add --no-cache dumb-init CMD ["dumb-init", "node", "dist/main.js"]

dumb-init runs as PID 1, properly forwards signals to NestJS, allowing app.enableShutdownHooks() to close database connections gracefully.

👤 Non-Root Security (USER node)

By default, Docker containers run as the root user. If an attacker discovers a remote code execution exploit in your application, they gain root access to the container and potentially the host kernel.

Hardening in Production stage
USER node COPY --chown=node:node --from=build \ /usr/src/app/dist ./dist

Running as node drops all superuser privileges, fulfilling CIS Docker Security benchmark requirements.

Nodemon & Hot Reload in Docker

Why and how we configured Nodemon specifically for the development stage.

💡 The macOS / Windows Bind Mount Gotcha

When Docker runs on macOS or Windows, it runs inside a lightweight Linux hypervisor. Standard Linux file watching uses the inotify kernel subsystem. However, filesystem events from macOS host disks do not always propagate through the Docker virtualization layer reliably.

To guarantee 100% reliable hot reloading, we configured nodemon.json with polling:

nodemon.json
{ "watch": ["src"], "ext": "ts,js,json", "exec": "ts-node -r tsconfig-paths/register src/main.ts", "legacyWatch": true, "pollingInterval": 500 }

legacyWatch: true polls the directory every 500ms, ensuring that code edits made in your IDE on Mac immediately trigger a restart inside the Linux container.

The Three Databases & Caching Layer

How PostgreSQL, MongoDB, and Redis are configured, seeded, and integrated.

🐘 PostgreSQL 16

Driver: TypeORM + pg

Init Script: docker/postgres/init.sql

Health Check: pg_isready -U postgres_user -d nest_docker_db

Provides relational data with foreign keys, transactional integrity, and native UUID generation (uuid-ossp).

🍃 MongoDB 7.0

Driver: Mongoose + @nestjs/mongoose

Init Script: docker/mongo/init.js

Health Check: mongosh --quiet --eval "db.adminCommand('ping').ok"

Used for audit logging and flexible JSON document storage with automated index creation.

⚡ Redis 7.0

Driver: ioredis with retry strategy

Config: docker/redis/redis.conf

Health Check: redis-cli -a password ping

In-memory cache with allkeys-lru eviction, hybrid RDB snapshots, and AOF durability.

The Schema Collision Bug & Solution

A critical real-world lesson on how TypeORM synchronize: true interacts with Docker database initialization scripts.

🚨
The Error in Container Logs:

QueryFailedError: column "email" of relation "users" contains null values

[nodemon] app crashed - waiting for file changes before starting...

🔍 The Root Cause
  1. init.sql created the users table manually with email VARCHAR(255) and seeded an admin user.
  2. In user.entity.ts, TypeORM defaults @Column() to character varying (without length limit).
  3. TypeORM's schema synchronizer saw the slight type mismatch and generated an ALTER TABLE command to drop email and re-add it as NOT NULL.
  4. Postgres rejected adding a NOT NULL column to an existing table with rows, crashing the container.
✅ The Professional Solution
  1. Cleaned init.sql: Stripped table creation DDL from init.sql so it only installs extensions (CREATE EXTENSION IF NOT EXISTS "uuid-ossp";).
  2. Delegated DDL to TypeORM: Let TypeORM create tables cleanly matching its entity metadata.
  3. Application Bootstrap Seeder: Moved seeding into UsersService.onApplicationBootstrap(). If 0 users exist, NestJS seeds the admin user safely on boot.

Nginx Reverse Proxy & Security

How Nginx acts as the gatekeeper for incoming HTTP traffic in production.

🛡️ Nginx Security & Performance Features (nginx/conf.d/default.conf)

1. Rate Limiting Protection

Protects your NestJS API against brute-force and DDoS attacks by enforcing a maximum of 20 requests per second per IP with a burst buffer of 40 requests.

2. Hardened Security Headers

Injects X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, and X-XSS-Protection to prevent clickjacking and MIME-type sniffing.

3. Gzip Payload Compression

Automatically compresses JSON, SVG, CSS, and JS responses to minimize network latency and bandwidth consumption.

4. Upstream Connection Pooling

Maintains persistent HTTP 1.1 keep-alive connections to upstream NestJS pods for maximum throughput.
